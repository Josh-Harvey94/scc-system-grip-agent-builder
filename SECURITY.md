# Sensitive information and security reports

Do not place patient-identifiable data, internal operational records, credentials, private tenant URLs or unredacted agent outputs in this public repository, issues or pull requests.

For a concern involving your organisation's data, use its established information-governance or security reporting route. For a repository flaw, provide a minimal synthetic reproduction. If a report would expose sensitive material, arrange a private contact route with the maintainer first instead of publishing the details.

Instructions are behavioural guidance, not access controls. Configure and test Microsoft 365 permissions independently. Keep golden answers and test material outside operational knowledge. All outputs need an accountable human reviewer.
